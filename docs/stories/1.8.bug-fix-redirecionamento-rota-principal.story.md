# Story 1.8: Corrigir redirecionamento indevido da rota principal

## Status

**Status:** Done
**Executor:** @dev
**Quality Gate:** @qa

## Story

**Como** usuário do BulkMail Pro,
**quero** acessar a tela principal de composição mesmo quando existe um envio em andamento,
**para** realizar novos envios independentemente do status de campanhas anteriores.

## Acceptance Criteria

1. A rota `/` deve permanecer na tela de novo envio mesmo quando `last_bulk_email_job_id` contém um job `pending` ou `processing`.
2. A abertura da rota `/` não deve consultar automaticamente o status do job armazenado anteriormente.
3. A retomada automática baseada em `last_bulk_email_job_id` deve ser removida do frontend.
4. Após um novo envio bem-sucedido, o usuário deve continuar sendo direcionado para `/status/{novoJobId}`.
5. O acesso direto e o refresh de `/status/{jobId}` devem continuar carregando e atualizando o job informado na URL.
6. Os links de acompanhamento existentes no Dashboard devem permanecer inalterados.

## Tasks / Subtasks

- [x] Remover a retomada automática da rota principal (AC: 1, 2, 3)
  - [x] Remover a leitura do `localStorage`, a consulta de status e o redirecionamento do `HomePage`.
  - [x] Remover imports e código sem uso resultantes da correção.
- [x] Remover a persistência obsoleta do último job (AC: 3, 5)
  - [x] Remover gravação e limpeza de `last_bulk_email_job_id` de `useJobStatus`.
  - [x] Preservar polling, paginação, callbacks e refresh baseados no `jobId` da URL.
- [x] Adicionar cobertura de regressão (AC: 1, 2, 4, 5)
  - [x] Cobrir o acesso a `/` com uma chave legada apontando para job ativo.
  - [x] Cobrir o redirecionamento após um novo envio bem-sucedido.
  - [x] Reexecutar o teste da página de status para confirmar acesso direto e polling.
- [x] Executar os quality gates e atualizar os registros da story.
