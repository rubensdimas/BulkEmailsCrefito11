# Story 4.3: Remover bind mount de arquivo único do `package.json` no Compose de desenvolvimento

## Status

Done

## Story

**Como** desenvolvedor do BulkMail Pro,
**quero** que `npm run` funcione dentro dos containers `backend` e `worker` mesmo depois de `git pull`, merge ou troca de branch,
**para** conseguir rodar scripts como `npm run user:admin -- reset-password` sem recriar os containers.

## Contexto

O `docker-compose.yml` montava `./backend/package.json:/app/package.json:ro` como arquivo único. Bind mounts de arquivo único ficam presos ao inode original: quando o git ou um editor substitui o arquivo (novo inode), o container continua listando `/app/package.json`, mas a abertura falha com `ENOENT`. Sintoma observado após o merge da Story 4.2:

```
npm error enoent Could not read package.json: Error: ENOENT: no such file or directory, open '/app/package.json'
```

A imagem `development` já copia `backend/package.json` no build, e mudanças nele implicam dependências novas, que exigem rebuild de qualquer forma.

## Acceptance Criteria

1. Os serviços `backend` e `worker` do `docker-compose.yml` não montam mais `./backend/package.json`.
2. Depois de substituir `backend/package.json` no host (novo inode), `docker exec bulkmail-backend npm run user:admin -- --help` e o equivalente no `bulkmail-worker` executam sem `ENOENT`.
3. O hot reload de `backend/src` continua funcionando (mount `./backend/src` inalterado).
4. O README informa que alterações no `backend/package.json` exigem `docker compose up -d --build backend worker`.

## Fora de escopo

- Mounts de arquivo único de `knexfile.ts` e `tsconfig.json` (mesmo risco, mantidos por decisão; recriar os containers resolve).
- `docker-compose.prod.yml` (não usa bind mounts de código).

## Tasks / Subtasks

- [x] Remover o mount de `package.json` do `backend` e do `worker` (AC1)
- [x] Atualizar o README com a nota de rebuild (AC4)
- [x] Rebuild e validação com substituição do arquivo no host (AC2)
- [x] Validar hot reload de `src/` (AC3)

## Dev Notes

- Recuperação imediata para containers já afetados: `docker compose up -d --force-recreate backend worker`.
- Não montar o diretório `backend/` inteiro: o Dockerfile define que o Compose de desenvolvimento monta apenas fontes.
